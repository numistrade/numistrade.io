# NumisTrade

Online marketplace for collectible and numismatic coins.

**Coins • History • Collection**

A static, client-side prototype that runs on GitHub Pages / any static host
(this repo has no build step and no backend — it's plain HTML/CSS/JS served as-is).

## Pages

| Page | Purpose |
|------|---------|
| `index.html` | Landing: hero, categories, featured coins, how it works |
| `products.html` | Catalog with category filter, search, sort, stock filter |
| `product.html?id=…` | Coin detail with quantity selector, add to cart / buy now |
| `cart.html` | Cart with quantity controls and order summary |
| `checkout.html` | Customer + delivery form, order summary, validation |
| `order-success.html` | Order confirmation + UPI instructions |
| `admin.html` | Password-gated catalog editor (add/edit/delete category posts) |

## Product data

Edit `data/products.json` (or use `admin.html`): each product uses the schema

```json
{
  "id": "coin-001",
  "name": "Example Indian Coin",
  "slug": "example-indian-coin",
  "category": "Republic India",
  "year": 1975,
  "country": "India",
  "denomination": "1 Rupee",
  "condition": "Very Fine",
  "price": 500,
  "currency": "INR",
  "stock": 3,
  "images": [],
  "description": "…",
  "featured": true,
  "active": true
}
```

All products are clearly marked `"demo": true` sample listings. Replace them
with real inventory before launch.

## Run locally

The site fetches `data/products.json`, which requires serving over HTTP:

```bash
python3 -m http.server 8000
```

Then open <http://localhost:8000/>. Opening the HTML file directly with
`file://` will not load the catalog (browser blocks the JSON fetch); use a
local server.

## GitHub Pages

All paths are relative, so the site works on GitHub Pages (enable Pages in the
repo settings — branch, root folder).

## Admin page (static, optional)

`admin.html` is a password-gated catalog editor: add, edit, group and delete
category posts (coin listings). First-time setup, run once locally:

```bash
node scripts/set-admin-password.js [username] [password]
```

This writes `data/admin.json` (a PBKDF2-SHA256 hash, never the plaintext
password). Publish your edits by **signing in → making changes → downloading
`products.json` → replacing it in the repo → git push → Pages rebuilds.**

**Important:** because this is client-side, the gate is *not* real security —
anyone can read the files and patch the JS in the browser. It stops casual
visitors only. A genuinely secure admin requires a server-side backend.
